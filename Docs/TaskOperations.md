# 작업 큐·자동 배정·운영 기록

현재는 [구간 예약·6대·배터리와 충전](FleetOperations.md)도 연결되어 있습니다. 기본은 3대·구간 예약이며, 아래 초기 작업 큐 시험 결과는 당시 검증 이력으로 보존합니다.

`Start.bat` → Unreal Editor에서 **Play** → 웹의 **작업 관제**를 엽니다. 기존 5,000㎡ 창고와 물리 지게차 3대에 중앙 작업 큐를 연결했습니다. 웹 기본 주소는 `http://127.0.0.1:4174/#tasks`이며 실행기가 다른 빈 포트를 선택했다면 해당 주소를 사용합니다. 웹만 열 때는 기존 `Website.bat`입니다.

## 작업 등록과 반복 운반

1. 센서와 위치 추정이 준비되어 웹에 **연결됨**이 표시될 때까지 기다립니다.
2. 등록 팔레트, 목적 슬롯 또는 자동 선택, 자동 선택 시 적재단, 우선순위(0~9, 큰 값 우선)를 고릅니다.
3. **묶음에 추가**로 서로 다른 팔레트 1~10개를 모아 **묶음 등록 요청**을 누릅니다.
4. **Unreal 수락**과 실제 작업 ID를 확인합니다. HTTP 전송 성공만으로 등록을 완료 처리하지 않습니다.
5. 빈 차량을 배정받은 작업이 기존 센서 제어로 픽업→운반→하역→주차 복귀를 수행합니다. 정상 복귀한 차량에는 다음 대기 작업을 자동 배정합니다.

세 차량보다 많은 작업을 등록할 수 있습니다. 세션당 최대 200개이며 열린 작업이나 복구 대기 작업의 팔레트는 중복 등록할 수 없습니다. 자동 목적지는 선택한 적재단의 경로 계획이 가능한 빈 슬롯 중 가까운 슬롯입니다. 명시한 목적 슬롯을 쓸 수 없다면 이유를 표시하고 대기하며 임의의 다른 슬롯으로 바꾸지 않습니다.

배정 순서는 우선순위 내림차순이며 같은 우선순위에서는 등록 순서를 따릅니다. 배정 가능한 차량 중 무적재 1.00m/s, 적재 0.85m/s와 고정 취급 여유를 적용한 명목 경로 시간을 비교합니다. 정지·무적재·정상 센서·유효 위치 추정·낮은 포크·수동 입력 없음 등의 조건을 만족해야 새 작업을 받습니다.

현재 기본은 **구간 예약**입니다. 공용 통로와 실제 점유 공간이 겹치면 차량을 배정받았어도 기다립니다. 초기 작업 큐 검증 당시의 작업 전체 예약은 `Start.bat -TrafficPolicy whole_job`으로 비교할 수 있습니다. 새 예약은 작업 우선순위 순으로 검토하고 이미 운행 중인 작업은 선점하지 않습니다. 장시간 6대 처리량 최적화 완료를 뜻하지는 않습니다.

## 상태와 복구

| 상태 | 의미 |
|---|---|
| 대기열 | 차량 배정 전. 웹에서 대기 취소 가능 |
| 차량 배정·수행 중 | 차량·팔레트·목적지와 고유 운반 작업 ID가 연결됨 |
| 정지·복구 대기 | 보호 정지·수동 개입·복구 유지. 자동 재시작하지 않음 |
| 고장 보류 | 센서 등 필수 조건 상실. 차량과 통로를 격리하고 재배정하지 않음 |
| 완료 | 기존 센서 픽업·하역 확인 및 주차 복귀가 실제로 완료됨 |
| 취소 | 배정 전 취소 또는 기존 차량 제어에서 안전한 취소 완료 |
| Play 종료 | 미완료 작업이 중단됨. 재실행 시 운행을 자동 복원하지 않음 |

웹에서는 **배정 전 작업만 취소**합니다. 배정 후 주행·복구는 Unreal Play 화면을 클릭한 뒤 조작합니다. **Tab** 차량 선택, **Backspace** 정지, **]** 조건 재검사 후 재개, **0** 취소/복구 유지, **X / Y** 비상정지/고장 확인입니다. 수동 **W/S·A/D·Z/C·Q/E·Space**는 기존 동작을 유지하며 자동 작업 중 수동 입력은 작업을 정지시킵니다. 삽입 중 중단이나 적재 상태의 고장은 [복구 조건](CampusFleet.md)에 따라 수동으로 처리합니다.

**Enter**는 선택 차량·현재 팔레트의 작업을 중앙 큐에 등록합니다. **F**는 현재 세 차량의 목표 팔레트를 한 묶음으로 등록하고 자동 배정합니다. **G**, **PageDown/Up**으로 새 작업의 팔레트·적재단을 선택합니다. 웹 차량 카드 선택은 Unreal의 조작 차량을 바꾸지 않습니다.

요청은 현재 Play 월드와 운영 실행 ID에 묶입니다. 응답을 못 받았다면 **같은 요청 확인·재전송**을 사용합니다. 동일 요청 ID는 중복 작업을 만들지 않습니다. 만료·중단·세션 변경 시 새 요청이 필요합니다. 이미 등록됐는지는 실제 작업 목록에서 확인합니다. 로컬 웹 연결이 끊겨도 기존 Unreal 작업은 자체 보호 제어를 계속하며 웹 단절을 차량 비상정지로 해석하지 않습니다.

## KPI와 저장 자료

운영 값은 Unreal에서 계산해 전송합니다. 웹은 표시·등록 요청·파일 비교를 수행합니다. 각 작업의 차량·운반 ID·상태 이력·픽업/하역 확인을 보존하므로 같은 차량이 다음 작업을 시작해도 이전 결과가 덮어써지지 않습니다.

| 지표 | 계산 범위 |
|---|---|
| 배정 전 대기 / 통로 대기 | 등록→배정 / 배정 후 경로 예약 대기 |
| 평균 수행 시간 | 완료 작업의 배정→주차 복귀 완료 |
| 평균 대기 시간 | 완료 작업의 배정 전 대기+통로 대기 |
| 처리량 | 완료 수×3600÷Play 시작 이후 시뮬레이션 초 |
| 차량 가동률 | 해당 차량의 주행·취급 시간÷Play 시뮬레이션 시간. 정지·통로 대기 제외 |
| 현재 판정 성공률 | 완료÷(완료+현재 고장 보류). 대기·취소·세션 중단 제외. 복구 후 변할 수 있음 |
| 추정 이동 거리 | 신선한 LiDAR 정합 속도의 적분. 저속 잡음·측정 공백 제외, 공백 시간을 별도 기록 |
| 속도 잔차 시간 | 바퀴 기반/스캔 기반 차체 속도 벡터 차이가 0.05m/s를 넘은 시간. 센서·필터 지연 포함, 타이어 접촉 슬립의 직접 측정이 아님 |
| 최대 포크 하중 | 유효한 좌우 포크 하중 센서 합의 최대값. 물리 내부 스텝의 충격 피크와 구별 |

모든 운영 시간은 **시뮬레이션 시간**입니다. 완료 작업이 없으면 평균값과 성공률을 0으로 꾸미지 않고 미정으로 표시합니다. 실시간보다 느리게 실행되는 PC에서는 실제 대기 시간이 더 깁니다. 거리·센서 하중은 추정·계측값이며 실차 인증 자료가 아닙니다.

매 시뮬레이션 1초 및 정상 세션 종료 시 `Saved/Operations/<실행 ID>/`에 다음 파일을 저장합니다.

- `session.json`: 조건·전체 작업·KPI·차량 가동률·최근 이벤트.
- `tasks.csv`: 전체 작업 29열. 네이티브와 웹 CSV는 열 순서가 다르므로 열 이름으로 읽습니다.
- `events.csv`: 상태 변경 이력(세션 최대 최근 10,000건).

웹의 **운영 작업 CSV / 현재 운영 기록 JSON**으로도 내려받을 수 있습니다. **저장 운영 기록 비교**에서 `session.json`을 최대 10개 골라 조건·처리량·평균 시간·정지를 비교합니다. 진행 중 저장본은 중간 결과이며, 같은 작업 구성과 종료 기준의 기록을 비교해야 합니다. 정상 Play 종료는 미완료 작업을 중단으로 기록하고 고장 원인은 보존합니다. 프로세스 강제 종료 시 마지막 주기 저장본까지만 남을 수 있습니다.

## 질량·마찰 조건 실험

`Config/CampusOperations.json`을 수정한 뒤 **다음 Play**에서 적용합니다. 기본 조건은 화물 400kg, 타이어 마찰계수 0.9, 노면 0.8입니다. 허용 범위는 화물 1~1000kg, 마찰계수 0~2입니다. `scenario_id`는 1~64자이고 `auto_dispatch`가 자동 배정 여부입니다. 질량은 실제 화물 강체에, 마찰은 실제 차량·노면 물성에 적용됩니다. 허용 입력 범위가 장비의 인증 적재 능력을 뜻하지 않습니다.

예를 들어 `scenario_id`를 `600kg-road03`, `cargo_mass_kg`를 600, `road_mu`를 0.3으로 바꾸고 같은 작업 묶음을 다시 시험합니다. 기본 파일을 유지하는 예시 조건도 제공합니다. 프로젝트 폴더의 터미널에서 `./Start.bat -CampusScenario Config/Experiments/Campus600kgRoad03.json`으로 실행하고 Play를 누릅니다. 사용자 JSON의 프로젝트 상대 경로나 절대 경로도 같은 인자에 사용할 수 있습니다. 웹에서 운행 중 물성을 덮어쓰는 기능은 제공하지 않습니다. 기본 조건으로 돌아올 때는 옵션 없이 `Start.bat`를 실행합니다.

## 검증

새 시험은 `Scripts/Test-TaskBoard.ps1`이며 기존 `Start.bat` 실행 체계를 유지합니다. 웹 프로토콜의 합성 자료 시험과 실제 Unreal 물리·센서·HTTP 연동 결과를 구분합니다. 실제 통과한 조건·빌드 해시·기록 위치는 [이번 검증 기록](References/TaskOperationsEvidence-20261116.json)에 정리합니다.

브라우저 연결 도구를 사용할 수 없어 새 관제 화면의 마우스 조작·시각 배치는 직접 확인하지 못했습니다. 정적 자산·요청 프로토콜과 실제 Unreal 데이터를 사용하는 HTTP 연동 범위로 검증합니다. 등록된 지도·팔레트 접근 위치를 사용하는 연구용 관제이며 임의 위치 팔레트 최적 접근과 3D SLAM은 포함하지 않습니다. 배터리·충전의 현재 범위는 위 후속 문서에서 확인합니다.
