# 관절 센서 첫 묶음

이후 승강 제어 연결은 [SensorLiftControl.md](SensorLiftControl.md)를 따른다. 높이·리미트·실린더 압력을 기본 integrated의 높이 제어/승강 제한에 연결했다. 나머지 센서의 자동 제어·팔레트 인식·삽입 판정·자율 주행은 후속이며 아래 당시 미연결 설명과 시험 수치는 이력이다.

2026-11-05 이후 묶음: [DynamicsSensors.md](DynamicsSensors.md). IMU·실린더 압력·좌우 포크 접촉 하중의 별도 측정 출력을 추가했다. 아래의 당시 미구현 설명과 검증 수치는 이력이며, 새 센서의 검증은 해당 문서를 따른다.

2026-10-31. 기본 integrated에 바퀴 엔코더 4개, 캐리지 높이 센서 1개, 상·하단 리미트 스위치 2개를 넣었다. 별도 실행 파일 없이 **루트 Start.bat → Editor에서 Play**로 사용한다. 기존 전방 깊이·후방 RGB-D는 유지한다.

## 실제로 무엇을 읽는가

| 장치 | 물리 입력과 출력 | 기본 설정 |
|---|---|---|
| 바퀴 출력축 엔코더 FL/FR/RL/RR | 휠과 장착부의 상대 회전을 내부 물리 스텝마다 풀어서 누적; signed count·각도·각속도 | 회전당 총 4,096 count, 100Hz |
| 포크 높이 센서 | 차체 좌표계에서 캐리지의 승강 변위; 바닥으로부터 포크 끝까지의 절대 높이는 아님 | 50Hz, 1mm 양자화, 잡음 σ 0.5mm, 바이어스 +0.5mm |
| 하단·상단 리미트 | 실제 캐리지 변위로 작동하는 가상 위치 스위치; 목표 높이로 판단하지 않음 | 100Hz, 종단 10mm 전 작동·15mm에서 해제, 20ms 디바운스 |

엔코더의 4,096은 quadrature 해독 이후의 총 count/회전이다. 리셋 시의 상대 영점을 사용하며 인덱스 탐색·원점 복귀는 아직 없다. 차체 yaw/pitch/roll을 제거한 휠 상대 회전으로 측정하므로 차량이 제자리에서 움직이거나 바퀴가 공회전해도 실제 축 회전이 남는다. `nominal_surface_mps`는 측정 각속도 × 설계 반경이며 차체 지면 이동 속도나 오도메트리 정답이 아니다.

상용 센서의 보정값이 아닌 가상 설계다. 양자화 간격이 실제 정확도를 뜻하지 않는다. `Config/JointSensors.json`에서 주기·해상도·잡음·지연·패킷 누락·스위치 위치를 설정하고 R 또는 Play 재시작으로 적용한다. 처음에는 종단 5mm 전의 스위치를 시험했으나 무적재 최대 실제 높이 약 2.0935m에서 상단이 닿지 않았다. 스위치 장착 위치를 10mm 전으로 정했고 질량·유압·행정·힘은 바꾸지 않았다. 하중 때문에 실제로 스위치까지 올라가지 못하면 상한 출력은 OFF를 유지한다.

## 지연·결측·고장

센서 취득은 물리 시계에서 수행하고, 화면 프레임과 별도의 취득 시각으로 각속도를 계산한다. 기본 전달 지연은 최소 20ms, 패킷 누락 확률은 0.1%, 오래된 값 판정은 250ms다. GT 큐와 프레임 처리에 따라 실제 전달은 더 늦을 수 있어 capture/delivery/age를 따로 보낸다. 긴 프레임을 가짜 보간 표본으로 메우지 않는다. 대기 큐는 상한을 두고 초과를 집계한다.

Unreal 뷰포트에 포커스를 둔 뒤 **U**로 전체 관절 센서의 통신 중단을 주입하고 다시 U로 복구한다. 취득과 내부 카운트는 계속되지만 전송이 끊긴다. 기존 표본은 250ms 후 stale·사용 불가가 되고 측정값은 null로 전달한다. 복구 후 새 표본이 도착해야 유효해진다. 고장 중 쌓인 표본을 몰아서 재생하지 않는다. U는 현재 수동 구동을 차단하는 급정지 기능이 아니다. R은 물리 장면과 센서 표본·카운터·고장 주입을 함께 초기화한다.

리미트는 히스테리시스와 디바운스를 거치며 초기 안정화 전에는 알 수 없음으로 표시한다. 높이 범위를 넘는 잡음은 센서 범위로 포화시키고 clipped 플래그를 남긴다. 속도를 계산할 이전 표본이 없는 경우 각속도는 null이다. 시뮬레이션 정지 때 물리 시계도 멈추며, 웹의 별도 벽시계 수신 중단 표시와 구분한다.

## 웹·기록과 제어의 경계

웹 실시간 패널의 **엔코더·높이·리미트 센서 측정값**에서 각 축의 count·rad/s·나이, 높이, 리미트 ON/OFF, 유효 상태와 고장 주입을 확인한다. **센서 CSV 저장**은 실제 수신 센서값만 19열로 내보낸다. 물리 정답이나 차체 속도로 결측을 대신 채우지 않는다. 수신 전에는 버튼이 비활성이다.

`Saved/Telemetry/JointSensors-*.csv`는 최대 20Hz 상태 스냅샷을 기록하며 프레임 간격에 따라 더 낮을 수 있다. 취득 자체는 위의 100/50/100Hz이며 sequence와 취득 시각으로 확인한다. `truth_angle_rad`·`truth_height_m` 열은 센서 오차를 검증하는 진단용 정답으로 따로 이름을 붙였고 웹 센서 출력에는 넣지 않는다. 기본 물리 CSV와 실제 센서 CSV를 구분한다.

**새 센서 출력은 아직 주행·승강 제어에 연결하지 않았다.** 기존 수동 구동과 GT 기반 시험 제어는 유지한다. IMU, 근거리 삽입 센서, 하중·압력 센서, 팔레트 인식, 센서 기반 제어·고장 정지 인터록·SLAM은 이번 묶음에 포함하지 않는다. 리미트 출력이 곧 안전 인터록이나 안전 등급을 뜻하지 않는다.

## 검증

최종 센서 DLL의 단위 시험은 **43/43** 통과했다. 상대 축 회전·여러 회전의 unwrap·차체 회전 제거, count와 취득 시계, 지연·타임아웃·복구, 스위치 히스테리시스·디바운스, 잡음·바이어스·리셋을 검사한다. 첫 Native CSV 검증에서 단정밀도 π 상수로 인한 환산 차이를 찾아 배정밀도로 수정했다.

네이티브 **8/8 실행**은 센서 전체 왕복·전후/횡이동·회전의 60FPS/960Hz, 30FPS/960Hz, 60FPS/1920Hz와 통신 고장 1개, 기존 운반·경사 제동·한쪽 턱·무마찰 4개다. 상·하단 스위치 작동, 정/역방향 count, 최소 지연, 양자화·잡음 오차 범위와 고장 복구를 실제 CSV로 확인했다. 관측 엔코더 취득률은 약 99.9991~99.9998Hz였다. 무마찰에서는 차체가 거의 정지해도 엔코더가 휠 공회전을 측정하는 것을 검사했다.

정상/고장 실행 사이 위치·속도·포크 높이·하중·에너지 기록의 최대 차이는 CSV 정밀도에서 0이었다. 앞선 물리 기준 DLL과도 운반·경사 제동·한쪽 턱의 같은 기록을 비교해 차이가 0임을 확인했다. 이는 비교한 조건에서의 일치이며 모든 조건의 수학적 동일성 증명은 아니다.

실제 웹 **1,091프레임**, 고장 후 stale 24프레임·복구 5프레임과 **19열/6,546행 CSV**를 확인했다. 공유 CSV 내보내기 함수의 실제 데이터 구성을 검증했으며 브라우저 DOM 클릭은 자동화하지 않았다. 기존 전방·후방 카메라의 실제 GPU 깊이/범위·지연·RGB-D 동기 회귀도 통과했다. 이전 물리 기준 빌드의 32조건·38단위·56FPS 기록은 이번 센서 빌드의 새 측정값으로 바꾸어 부르지 않는다.
