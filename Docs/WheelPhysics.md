# 바퀴 물리 시험장 — 0.2

## 이번 단계의 범위

센서와 자율주행을 연결하기 전에 **바퀴 회전과 차체 운동 사이의 힘 전달**을 검증한다.
앞바퀴 2개 구동, 뒷바퀴 2개 조향, 4개 바퀴에 제동 토크를 적용하는 학습용 구성이다.
특정 제조사 지게차 사양을 재현하거나 안전성을 검증한 모델이 아니다.

`Start-DriveLab.bat`로 실행한다. `Start-Lab.bat`의 기존 승강 시험장은 변경하지 않는다.
주행 시험장의 마스트·포크는 고정된 시각 형상이다. 승강부와 주행부의 동역학은 아직 통합하지 않았다.
주행 제어는 키보드 수동 입력만 받으며 팔레트 인식·장애물 센서·경로 추종은 추가하지 않았다.
자동 입력은 명시적으로 실행한 테스트/화면 캡처에서만 사용한다.

## 왜 별도 평면 동역학인가

Unreal은 화면과 입력을 담당하고, `WheelModel`이 SI 단위로 차체 X/Y 이동·수직축 회전과
각 바퀴의 회전을 계산한다. 그 결과를 렌더링용 Actor에 반영한다. 바퀴 메시는 Chaos 강체가 아니다.
`목표 속도 × 프레임 시간`으로 차량을 이동시키거나 차체 속도로 바퀴 애니메이션을 만드는 모델과 달리,
차체 속도와 바퀴 각속도가 독립 상태라서 실제 모델 내 헛돌기·잠김·횡방향 미끄러짐이 가능하다.

첫 단계의 가정:

- 무한하고 평탄한 지면, 항상 네 바퀴가 접지. 렌더링 바닥은 200×200 m.
- Z 이동, 롤·피치, 서스펜션, 요철, 전복, 차체·장애물 충돌은 계산하지 않는다.
- 수직 하중은 무게중심과 축간거리로 정한 정적 값. 급가속·급제동의 하중 이동은 없다.
- 전체 노면에 동일한 마찰계수. 정지/운동 마찰계수는 하나로 통합하고 타이어 변형은 제외한다.
- 조향 액추에이터는 각속도가 제한된 이상적 장치이며 조향 토크·소비전력은 아직 모델링하지 않는다.
- 구동 토크는 감속기 출력축 기준이다. 모터 전류·배터리·기어 손실 모델은 없다.

차량 질량 키 `M`은 가상 밸러스트 조건이다. 총질량과 요 회전관성을 같은 비율로 바꾸고
무게중심·바퀴 회전관성은 유지한다. 실제 화물을 포크에 싣는 시험이 아니다.

## 힘과 회전의 연결

1. 운전자 입력 → 앞바퀴 구동 토크. 브레이크를 누르면 구동 명령은 차단한다.
2. `I × 각가속도 = 구동 토크 - 접지력 × 반지름 - 제동·구름저항 토크`.
3. 각 접점의 차체 속도는 `차체 병진 속도 + 요 각속도 × 접점 위치`.
4. `슬립 속도 = 바퀴 원주속도(rω) - 접점의 전후 속도`. 0이면 순수 구름에 가깝다.
5. 종·횡 접촉 충격량을 함께 풀고 `sqrt(Fx² + Fy²) ≤ μN`인 마찰 원 안으로 제한한다.
6. 접지력 합계가 차체를 가속하고, 접점 위치에서 발생하는 모멘트가 차체를 선회시킨다.

고정 1/240초 간격으로 진행하는 누적 충격량 반복 계산기이며, 매 간격마다 접지와 제동을
좌우 대칭을 보존하는 동시 갱신으로 64회 반복한다(완화 계수 0.5). 제동은 회전 반대쪽으로만 작용하는 제한된 충격량이라서 정지 후
반대 방향으로 차량을 밀지 않는다. 구름저항은 `Crr × N × r`의 저항 토크로 근사한다.
슬립률의 분모는 `max(0.1, |접점속도|, |원주속도|)`로 제한하므로 정지 근처에서도 발산하지 않는다.
이 슬립률은 표시·기록용이며 실측 타이어 곡선에 맞춘 모델이 아니다.

렌더링 프레임 사이에 필요한 고정 스텝을 여러 번 실행한다. 프레임 지연이 0.25초를 넘으면
그 이상 시간을 버려 시뮬레이션 시간이 실제 시간보다 느려진다. 큰 시간 간격을 물리식에 넣지는 않는다.

## 직접 비교하기

| 키 | 기능 |
|---|---|
| W / S | 전진 / 후진 토크 |
| A / D | 좌 / 우로 차체를 돌리는 후륜 조향 |
| Space | 제동 |
| R | 원점에서 리셋, 기존 기록 저장 |
| F | 마찰계수 0.8 → 0.25 → 0.08, 리셋 |
| M | 질량 2,200 → 3,200 → 1,500 kg, 리셋 |
| T | 앞바퀴별 구동 토크 650 → 1,000 → 300 N·m, 리셋 |
| C | 카메라 변경 |

처음에는 조향 없이 W를 누른다. F로 낮은 마찰로 바꾸고 반복하면 차체 속도는 느리지만
앞바퀴 원주속도와 슬립 속도는 커지는 것을 확인할 수 있다. 제동거리 비교는 **같은 초기 속도**여야
의미가 있으므로 자동 모델 시험은 두 노면 모두 3 m/s에서 제동을 시작한다.

HUD는 모델의 참값을 보여 주는 계기판이며 센서를 흉내 내지 않는다. 바퀴의 밝은 선은 실제 계산된
회전각을 따라간다. 빠르게 회전할 때 화면 샘플링에 의한 역회전 착시가 생길 수 있다.

## 기록과 시험

`Saved/Telemetry/Wheels_*.csv`: 10 Hz, 바퀴별 한 행. 차량 위치·속도·가속도·요각,
입력, 마찰, 질량, 바퀴 각속도·원주속도·슬립, 수직 하중·종횡 힘·구동 토크·조향각·운동에너지 기록.
현재 가속도 항목은 전방 속도의 시간 변화율이며 횡가속도를 포함한 전체 가속도 벡터는 아니다.
5초마다, 리셋 및 정상 종료 시 저장한다. `.meta.txt`에는 엔진 버전, 계산 간격, 기본 설정과 실제
활성 파라미터를 보관한다. CSV 전체를 메모리에 보관하므로 장시간 시험은 주기적으로 리셋한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Test-Wheels.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Test-Wheels.ps1 -Mode Runtime -Fps 30
powershell -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Test.ps1
```

모델 시험: 설정·수직 하중 합계, 회전관성, 무마찰 공회전, 접지력·슬립, 같은 속도에서 제동거리,
제동 에너지 감소, 정지 유지, 구름저항, 마찰 원, 후륜 조향·후진, 시간 간격 수렴.
런타임 시험: 정상 주행 후 제동, 낮은 마찰의 헛돌기 후 제동, 후륜 조향.
실행 결과는 `Docs/WheelValidation.md`에 정리한다.

현재 범위의 모델 검증과 실물 정합성 검증을 구분한다. 다음 물리 확장은 실제 타이어 파라미터,
