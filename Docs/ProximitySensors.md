# 포크 근거리·물체 존재 센서

이후 승강 제어 연결은 [SensorLiftControl.md](SensorLiftControl.md)를 따른다. 높이·리미트·실린더 압력을 기본 integrated의 높이 제어/승강 제한에 연결했다. 나머지 센서의 자동 제어·팔레트 인식·삽입 판정·자율 주행은 후속이며 아래 당시 미연결 설명과 시험 수치는 이력이다.

2026-11-05. 기본 integrated에 거리 4개와 존재 감지 4개를 추가했다. **루트 Start.bat → Unreal Editor에서 Play**로 사용한다. **L**은 광선 표시, **U**는 관절·IMU/압력/하중·이 묶음의 통신 중단/복구, **R**은 장면과 센서의 새 시작이다. 별도 시작 배치 파일은 없다.

| 채널 | 위치·방향 | 기본 범위 |
|---|---|---|
| heel_left / heel_right | 각 포크 뿌리에서 1cm 앞으로, 포크 윗면보다 3cm 위에서 전방 | 거리 0.02~1.5m |
| tip_left / tip_right | 각 포크 끝에서 1cm 앞으로, 윗면보다 3cm 위에서 전방 | 거리 0.02~1.5m |
| presence_left_near / presence_right_near | 포크 길이 20% 지점, 윗면보다 1mm 위에서 위쪽 | 물체 존재 0~0.15m |
| presence_left_far / presence_right_far | 포크 길이 80% 지점, 윗면보다 1mm 위에서 위쪽 | 물체 존재 0~0.15m |

센서 방향과 위치는 각 위치에 해당하는 **실제 포크 강체 조각**을 따라간다. 캐리지를 올리면 함께 올라가며 포크의 휨·기울기도 반영한다. 두 번째 랙 높이에 별도의 고정 센서를 두지 않는다. 1·2단에서도 같은 포크 센서를 쓴다.

설정은 [Config/ProximitySensors.json](../Config/ProximitySensors.json)에서 바꾸고 R 또는 Play 재시작으로 적용한다. 모든 범위·잡음·지연·장착 위치는 가상 설계다. 실제 제품 보정값이나 구매 가능한 완제품 설계를 확정한 것은 아니다. 센서 외형 메시·추가 질량·브래킷 충돌은 넣지 않았다.

## 실제로 무엇에 반응하는가

게임 스레드의 20Hz 취득 시점에, 읽기 잠금을 건 Chaos의 실제 **simulation shape**에 단일 광선을 쏜다. PhysicsOnly 창고 고체를 포함하고 QueryOnly 장식용 메시·NoCollision 시각 모델·probe는 제외한다. 용접 팔레트의 판재 전체를 읽으며, 바운딩 박스로 팔레트 구멍을 막지 않는다. AABB는 광선 후보를 줄이는 용도이고 최종 반환은 각 충돌 형상의 raycast다. 차체·포크·바퀴 등 자기 장비의 강체는 제외한다. 매 취득 때 물체 목록을 갱신하며, 물리 재질·충돌 프로필·힘을 변경하지 않는다.

가장 가까운 물체가 최소 거리 안에 있으면 **too_close**이며, 그 뒤 물체의 거리를 대신 보이지 않는다. 광선 시작점이 고체 내부이면 거리 0의 가림으로 취급한다. 최대 거리 안에 반환이 없으면 **no_return**이며 거리 0이나 최대 거리로 채우지 않는다. 최대 범위 밖의 물체는 광선으로 측정하지 못하므로 기본적으로 반환 없음이다.

존재 센서는 별도의 **이상적인 짧은 광선 차단 스위치**다. 거리 센서의 최소 거리 값을 역산하지 않는다. 감지 구간 안의 표면은 ON, 광선이 비어 있으면 OFF이며 두 전환 모두 기본 50ms 디바운스를 거친다. 시작·긴 취득 공백·광학 누락 직후에는 신호가 안정될 때까지 알 수 없음이다. 물체가 없는 정상 OFF와 센서 고장·결측은 구분한다.

**물체의 actor 이름·팔레트 위치·진짜 삽입 깊이로 측정 결과를 만들지 않는다.** 팔레트의 판재뿐 아니라 화물·선반·다른 고체에도 반응한다. 네 존재 신호가 모두 ON이어야 완전 삽입이라는 규칙도 넣지 않았다. 팔레트 판재 사이 틈에서는 정상적으로 OFF일 수 있고, 다른 물체가 있어도 ON일 수 있다. 구멍 위치 추정·팔레트 인식·삽입 깊이 추정은 센서 융합과 제어 단계의 별도 작업이다.

단일 광선 모델이며 실제 광학 빔 폭·반사율·검은 표면·태양광·다중경로·오염·센서 자체 하우징 가림을 재현하지 않는다. 가까운 구멍 가장자리도 광선이 지나가지 않으면 검출하지 못한다. 이 묶음으로 차량 주변 전체 충돌 감지가 끝났다는 뜻은 아니다.

## 취득·오차·상태

- 실제 게임 스레드 취득 목표 20Hz. 실제 취득 시각과 sequence를 보존하며 프레임 사이의 가짜 표본을 채우지 않는다. 물리 내부 스텝의 전수 기록은 아니다.
- 거리 바이어스 +1mm, 가우시안 잡음 σ 1mm, 양자화 1mm. 해상도는 실제 정확도나 실측 보정을 뜻하지 않는다.
- 광학 누락 0.1%와 통신 패킷 누락 0.1%를 별도로 적용한다. 최소 전달 지연 30ms, 오래된 값 판정 300ms, 채널별 고정 seed다. GT 프레임 간격만큼 추가 전달 지연이 생길 수 있다.
- `status`·`transport_valid`는 수신 신선도, `reading_status`·`measurement_valid`는 측정 사용 가능 여부다. 새 no_return 패킷은 통신이 정상이어도 거리는 사용할 수 없다. 존재 센서의 새 OFF는 정상 측정이다.
- stale·광학 누락·초기 안정화 등 사용 불가 시 거리/ON-OFF를 웹 null, CSV 빈칸으로 보낸다. 물리 정답으로 대체하지 않는다. 통신 복구 후 새 패킷이 와야 정상화된다.
- `-ProximitySensorFault=all|채널ID`는 검증용 6~8초 통신 고장이다. U와 이 플래그는 비상 정지나 실제 안전 등급의 인터록이 아니다.

## 화면·기록

웹 **포크 근거리·물체 존재 센서 측정값**에서 8개 채널을 확인한다. **근거리·존재 CSV**는 실제 수신 센서값만 17열로 저장한다. 이전 관절·IMU/압력/하중·물리 계측 CSV는 유지한다. L의 광선은 장면 검사에 쓰는 물리 진단 표시이며 컨트롤러의 측정 데이터가 아니다.

`Saved/Telemetry/ProximitySensors-*.csv`는 최대 20Hz 상태 스냅샷 22열이다. `truth_hit`·`truth_range_m`과 원점/방향은 오차·장착 추종 검증을 위한 진단이다. 웹에는 물체 ID·진짜 거리·진짜 삽입 깊이를 보내지 않는다. 웹의 `diagnostic_origin_world_m`·`diagnostic_beam_world`는 장착 검사 좌표이며 측정 자세·SLAM 출력으로 쓰지 않는다.

**주행·승강 자동 제어와 고장 정지 인터록은 아직 연결하지 않았다.** 현재 랙 시험의 이동·승강 제어는 기존 GT 기반 검증 장치다. 센서로 팔레트를 찾아 자율 삽입하는 구현과 구별한다.

## 검증 재현

`Scripts/Test-ProximitySensors.ps1`은 별도 검증 도구이며 사용자 실행은 계속 Start.bat 하나다. 실제 형상의 가림/PhysicsOnly/장식 메시/고체 내부/용접 팔레트 구멍·중앙 받침 7개 검사, 운반 정상/통신 고장, 랙 1·2단 인출, 30FPS 운반을 실행한다. Python은 실제 CSV의 취득률·지연·결측·양자화/잡음·복구·높이 추종·감지 변화를 검사한다. 단위 시험은 거리 상태 구분·스위치 양쪽 전환의 디바운스·누락/복구·seed/잡음/설정 검증을 포함한다.

## 이번 빌드의 결과

- 단위 **52/52**, 네이티브 **6/6 조건**, 별도 실제 형상 검사 **7/7**과 CSV 독립 검증이 통과했다. 이전 묶음의 시험 수치를 이번 결과로 재사용하지 않았다.
- 실제 용접 팔레트의 구멍 통과·중앙 받침 가림, PhysicsOnly 고체·QueryOnly 장식 제외, 가까운 가림 뒤의 잘못된 거리 반환 방지, 광선 원점이 물체 안인 경우를 검사했다.
- 랙 1단 인출에서 왼쪽 뿌리 쪽 존재 센서는 ON 471개·OFF 815개 스냅샷을 기록했다. 2단은 ON 548개·OFF 910개, 최대 센서 월드 높이 약 **2.1493m**였고 1.95m 위에서 ON 표본 **446개**가 있었다. 판재 사이 틈 때문에 신호가 달라지는 것을 유지했으며 모든 채널 ON을 요구하는 삽입 완료 판정은 넣지 않았다.
- 같은 운반의 정상/통신 고장 실행은 위치·속도·포크 높이·하중·에너지 등 9개 물리 CSV 항목의 최대 차이가 0이었다. 직전 IMU/압력/하중 센서 DLL의 동일 운반 기록과도 같은 9개 항목의 차이가 0이었다. 비교한 조건의 로그 정밀도 내 일치이며 모든 조건의 수학적 동일성 증명은 아니다.
- 실제 웹 **461프레임**, stale **24프레임**·복구 **5프레임**, 거리 반환 없음 **118관측**, 존재 ON/OFF 모두와 **17열·3688행 CSV**를 확인했다. 공유 내보내기 함수와 실제 수신 스트림을 검증했고 브라우저 DOM 클릭은 자동화하지 않았다. 기존 관절·IMU/압력/하중 CSV, live-state JS 회귀도 통과했다.
- 기존 전방 깊이·후방 RGB-D의 실제 GPU 거리·near/far 결측·지연·RGB-D 동기 회귀가 통과했다. 이번 빌드의 새 FPS 벤치마크나 정밀 롤러 전체 조건 검증을 수행했다고 주장하지 않는다.
