# IMU·유압 압력·좌우 포크 접촉 하중 센서

이후 승강 제어 연결은 [SensorLiftControl.md](SensorLiftControl.md)를 따른다. 높이·리미트·실린더 압력을 기본 integrated의 높이 제어/승강 제한에 연결했다. 나머지 센서의 자동 제어·팔레트 인식·삽입 판정·자율 주행은 후속이며 아래 당시 미연결 설명과 시험 수치는 이력이다.

이후 근거리 센서 묶음은 [ProximitySensors.md](ProximitySensors.md)를 따른다. 기본 integrated에 포크 전방 거리 4개·위쪽 물체 감지 4개를 추가했으며 아래 당시 미구현 설명·시험 수치는 이력이다.

2026-11-05. 관절 센서 다음 묶음이다. **루트 Start.bat → Unreal Editor에서 Play**로 실행한다. 기존 두 카메라와 엔코더·높이·리미트를 유지하며, 기본 integrated의 웹 실시간 패널에 새 센서 측정값을 보낸다. U는 관절 센서와 이 묶음의 통신 중단/복구, R은 물리 장면·센서 시계·큐·고장·CSV를 새로 시작한다. U는 비상 정지가 아니다.

## 무엇을 측정하는가

| 장치 | 물리 입력·측정 의미 | 기본 가상 사양 |
|---|---|---|
| 차체 6축 IMU | 장착점 속도의 구간 변화에서 중력을 뺀 비력 3축, 차체 각속도 3축 | 100Hz, ±8g / ±500deg/s |
| 실린더 압력 센서 | 실제 유압 내부 스텝의 실린더 포트 게이지 압력 | 100Hz, 0~16MPa, 양자화 1kPa |
| 좌·우 포크 계측 패드 | 해당 포크와 팔레트 사이 접촉 충격량을 차체 위쪽 축으로 투영하고 취득 구간 시간으로 나눈 힘 | 각각 100Hz, ±20kN, 양자화 1N |

설정은 [Config/DynamicsSensors.json](../Config/DynamicsSensors.json)에서 바꾸고 R 또는 Play 재시작으로 적용한다. 센서 상용 제품의 측정 사양을 보정한 결과가 아닌 **가상 설계 값**이다. 하중 센서는 기존 접촉을 읽는 이상적인 계측 패드이며 실제 로드핀·스트레인 게이지의 부착 위치, 변형률–전압 회로, 크로스토크, 온도 보상 모델을 구현한 것은 아니다. 추가 센서 강체나 접촉력을 만들지 않는다. 현재 패드의 입력은 **포크–팔레트 접촉**으로 한정하며 랙·바닥·화물의 직접 접촉을 감지하는 전면 힘 센서가 아니다.

포크 값은 포크가 팔레트에 가한 차체 축 방향 접촉력이다. 가속·기울어짐·옆면 접촉·한쪽 들림 때 단순 `화물 질량 × 중력`과 달라진다. 포크 자중을 포함한 뿌리 굽힘력이나 팔레트 없는 화물 질량을 직접 출력하지 않는다. 압력도 체인 배율·이동부 자중·씰 저항·가속도·배관 과도응답을 포함하므로, `압력 × 면적 / 중력`을 화물 질량으로 표시하지 않는다.

## IMU 좌표·시간·장착점

장착점은 기본 **차체 질량중심에서 위로 0.4m**, 방향은 차체와 같다. 회전 중 장착점 속도는 `v_COM + ω × r`로 계산하므로 질량중심과 떨어진 센서의 구심·접선 가속도가 포함된다. 질량중심 오프셋·장착 위치는 진단용 설정이며 측정 자세·위치나 SLAM 출력을 대신하지 않는다.

`f_sensor = R⁻¹(Δv_point / Δt − g_world)`. 가속도는 인접 취득 순간 사이 속도 변화의 평균을 현재 센서 축으로 표현한다. 각속도는 현재 취득 순간의 차체 각속도다. 정지·수평이면 Z 비력은 약 +9.81m/s², 이상적인 자유낙하에서는 0이다. 첫 취득 때에는 속도 기준만 저장하고 가속도 패킷을 만들지 않는다. 보간으로 표본을 채우지 않는다. 이 구간 차분은 아날로그 anti-alias 필터의 전체 전달함수나 충격 피크 수렴을 재현한 것이 아니다.

축은 **Unreal의 X 전방·Y 우측·Z 위 좌표와 원시 회전 부호**다. ROS REP-103 우수 좌표로 변환하거나 AHRS 자세를 융합하지 않았다. 중력은 고정 숫자로 출력하지 않고 현재 World 중력 설정을 사용한다. 지구 자전·자기계·랜덤워크·온도에 따른 IMU 드리프트는 이번 범위에 없다.

취득은 Chaos 내부 스텝의 물리 시계에서 수행한다. 설정 주기를 지난 첫 실제 해결 시점에서 읽으므로 960Hz/100Hz의 각 간격은 완전히 같지 않을 수 있다. 센서 모델은 실제 취득 시각과 sequence를 보존한다. 압력은 같은 물리 적분 구간의 실린더 상태 갱신 직후, IMU와 하중은 PostSolve에서 읽는다. 완전히 같은 아날로그 노출 시점으로 강제 동기화한 센서 패키지가 아니다.

## 오차·지연·고장

- 가속도: 축별 고정 바이어스 +0.01m/s², σ 0.02m/s², 양자화 0.001m/s².
- 자이로: 축별 +0.0005rad/s, σ 0.001rad/s, 양자화 0.0001rad/s.
- 압력: +5kPa, σ 3kPa. 좌우 하중: 각각 +1N, σ 2N.
- 최소 전달 지연 20ms, 패킷 누락 0.1%, 오래된 값 판정 250ms. 채널별 결정적 난수 seed를 사용한다.
- 범위를 벗어나면 포화시키고 `clipped_mask`로 해당 축을 표시한다. 양자화 간격을 실제 정확도로 부르지 않는다.
- 통신 중단 중에도 물리와 센서 취득은 계속된다. 캡처·전달 시점에 손실을 처리하고 밀린 패킷을 복구 후 재생하지 않는다. 마지막 값은 타임아웃 뒤 stale이 되며 웹 측정값은 null, CSV는 빈칸이다.
- 큐 상한 1,024개와 overflow 집계가 있으며, 잘못된 설정은 경고 후 센서 생성을 중단한다. 수동 물리에 임의의 대체 센서값을 넣지 않는다.

`-DynamicsSensorFault=all|imu|lift_pressure|fork_load_left|fork_load_right`는 검증용 6~8초 통신 고장이다. 사용자는 계속 Start.bat 하나를 쓴다. 고장 주입 여부 필드는 시험 진단용이며 실제 제어기가 즉시 고장을 알 수 있다는 뜻이 아니다.

## 웹과 저장

웹의 **IMU·압력·좌우 포크 하중 센서 측정값**에서 측정·유효 상태·표본 나이·포화를 확인한다. 기존 접촉/유압 물리 계측과 분리한다. **IMU·압력·하중 CSV**는 실제 수신값만 21열로 내보낸다. 수신이 없거나 stale이면 물리 정답으로 대체하지 않는다. Unreal 연결 정지 때는 별도 수신 중단 표시를 따른다.

`Saved/Telemetry/DynamicsSensors-*.csv`는 최대 20Hz 수신 상태 스냅샷(23열)이다. 센서 취득 100Hz 전체의 원시 전수 기록과 구별한다. `truth_0..5`는 오차 검증을 위해 별도로 명명한 물리 진단 열이며, 웹 `dynamics_sensors`와 웹 센서 CSV에는 포함하지 않는다. IMU의 value/truth 0..2는 m/s², 3..5는 rad/s, 압력 0은 Pa, 하중 0은 N이다.

**새 측정값을 구동·승강 제어에 연결하지 않았다.** 근거리 삽입/팔레트 존재 센서, 팔레트 인식, 센서 융합·오도메트리, 제어기·고장 정지 인터록·충돌 회피·SLAM은 후속 묶음이다. 이번에 안전 등급이나 실차 정격을 검증한 것은 아니다.

## 검증 방법과 물리 근거

`Scripts/Test-DynamicsSensors.ps1`은 기본 조건 6개(정지·운반·편심 양중·관절 왕복/전후횡이동/회전·한쪽 턱·경사 제동), 운반 통신 고장, 30FPS 운반, 1920Hz 운반을 실행한다. Python 검증기는 실제 Native CSV의 취득률·지연·스케일·오차·양자화·포화·결측·복구와 정하중·편심·압력 증가를 검사한다. 단위 시험은 중력/기울임/자유낙하·장착점 회전 효과·통신·포화·바이어스/잡음/리셋을 포함한다. 실제 웹 스트림과 공유 내보내기 함수도 별도 검증한다. 검증 결과와 해시는 아래 근거 파일에 기록한다.

비력과 자이로의 정의는 [VectorNav Inertial Navigation Primer](https://www.vectornav.com/docs/default-source/educational-material/inertial-navigation-primer-r3.pdf)를 참고했다. 유압 양중에서 압력으로 부하를 관측하는 원리는 [WIKA Electronic Pressure Measurement Handbook](https://microsites.wika.com/upload/Handbook_ElectronicPressure_en_co_34154.pdf), 동적 압력 기반 중량 추정의 추가 고려는 제조사 [Fluitronics Integrated Sensors](https://fluitronics.com/en/products-solutions/application-examples-solutions/integrated-sensors/)를 참고한다. 이 자료들이 위의 가상 센서 잡음/범위 설정이나 실제 센서 채택을 입증하지는 않는다.

## 이번 빌드의 결과

- 단위 **48/48**, Native **9/9** 및 실제 CSV의 독립 검증이 통과했다. 물리 파라미터는 바꾸지 않았다.
- 정지 IMU 평균 비력은 약 `[0.00944, 0.01112, 9.81930]`m/s²로 설정된 +0.01 바이어스를 포함한다. 평균 각속도는 각 축 약 0.0004~0.0006rad/s였다.
- 425kg 적재의 정지 구간에서 좌우 약 **2087.1 / 2084.0N**, 합 4171.1N을 측정했다(설정 중량 4169.25N). 편심 조건은 약 **1712.0 / 2459.2N**으로 달라졌다. 실린더 압력은 무적재 평균 약 **2.046MPa**, 적재 정지 구간 약 **6.216MPa**였다.
- 30FPS와 1920Hz 운반의 정지 구간 하중 합·압력은 기준 대비 사전에 정한 3% 이내였다. 회전 중 IMU 자이로와 가장 가까운 기존 물리 CSV yaw의 최대 차이는 약 0.04562rad/s로 0.05 기준 이내였다. 이 비교에는 20Hz 스냅샷과 내부 취득의 시각·단계 차이가 포함되므로 센서 자체의 보정 오차로 해석하지 않는다.
- 정상/통신 고장 운반의 위치·속도·포크 높이·하중·에너지 등 9개 물리 기록은 CSV 정밀도에서 최대 차이가 0이었다. 이전 관절 센서 빌드와 운반·한쪽 턱·경사 제동의 같은 9개 항목도 차이 0이었다. 비교한 조건의 일치이며 모든 상황의 동일성 증명은 아니다.
- 실제 웹 **538프레임**, 고장 후 stale **31프레임**, 복구 **7프레임**, **21열·2152행 CSV**를 검증했다. 공유 내보내기 함수와 실제 수신 스트림을 확인했으며 브라우저 DOM 클릭은 자동화하지 않았다. 기존 관절 센서 CSV 및 live-state JS 회귀도 통과했다.
- 기존 전방·후방 카메라의 실제 GPU 깊이·거리 범위·지연·RGB-D 동기 회귀가 통과했다. 이번 빌드의 새 FPS 벤치마크나 정밀 롤러 전체 재검증을 수행했다고 주장하지 않는다.
