# 창고 기반 1~4 묶음: 차량·팔레트·재고·센서

현재 실행·관제 조작과 5~6 묶음 상태는 [CampusFleet](CampusFleet.md)을 확인하세요. 아래 내용은 맵·기반 작업의 시험 이력입니다.

기존 한 대 시험장의 물리·센서를 새 창고에서 사용하는 단계입니다. 자동 배차·창고 전체 경로 계획·교차로 예약·다중 차량 웹은 5~6번 후속 범위입니다. 이번 모드에서 지게차는 수동 조작합니다.

## 실행

루트 **Start.bat → Play → 게임 화면 클릭**으로 실행합니다. 기본 integrated는 새 창고와 기존 대시보드를 엽니다. 기존 단일 차량 자동화는 **`Start.bat -Map lab`**로 유지합니다. 대시보드의 다중 차량 연결은 다음 묶음이므로 이번 창고 모드의 값은 Unreal HUD에서 확인합니다. 대시보드에 가짜 차량 값이나 선택되지 않은 다른 차량의 값을 보내지 않습니다.

| 키 | 동작 |
|---|---|
| Tab | AGV-01 → 02 → 03 선택, 이전 차량 제동 |
| End | 선택 차량 수동 운전·추적 화면으로 복귀 |
| W/S, A/D, Z/C | 전후, 회전, 메카넘 횡이동 |
| Q/E, Space | 포크 하강/상승, 누르는 동안 제동 |
| Shift 유지 | 기존 수동 저속 접근 모드. 장애물을 확인하며 팔레트에 접근 |
| G | 다음 사용 가능한 팔레트를 작업 대상으로 예약·활성화 |
| I, L, P, O | LiDAR/포크 근거리 광선, 선택 차량 카메라 켜기/끄기, 후방 RGB/깊이 전환 |
| X, Y | 선택 차량 비상정지, 정지 상태에서 고장 확인 |
| 1/2/3/4 | 전체/외부/실내/서비스 구역 자유 카메라. 차량들은 제동 |
| H, Home | 지붕 전환, 전체 조망 |
| Shift+F1, Esc | PIE 마우스 해제, PIE 종료 |

시작 직후에는 이동·승강 키를 놓고 HUD에 센서 준비와 지도 정합이 표시될 때까지 기다립니다. 팔레트 주변에서 `obstacle_hold`가 뜨면 주변을 확인한 뒤 Shift를 유지하며 저속 접근합니다.

자유 카메라에서는 WASD/마우스가 카메라를 움직이고 Q/E는 상하 이동입니다. 운전 화면에서는 같은 키가 지게차를 조작합니다. G는 인식 성공이나 자동 접근 명령이 아니며, 작업 대상으로 삼을 재고 ID를 운영자가 선택하는 기능입니다. 대상 변경의 하중 조건은 실제 포크 하중 센서로 확인하여, 다른 팔레트를 잘못 지지하고 있는 경우도 변경을 거부합니다. 지지 중인 화물을 놓거나 차량이 정지하기 전에는 대상을 바꿀 수 없습니다.

## 차량과 환경의 소유권

`ACampusOperations`가 창고의 공유 바닥 3개, 정적 조사 지도, 랙 슬롯과 재고를 관리합니다. 각 `AStabilityLab` 인스턴스는 고유 차량 ID와 자기 차체·바퀴 4개·포크·유압·센서·제어 상태를 가집니다. 기존 차량별 계산 모듈을 재사용하며 시험장 바닥이나 시험용 랙·팔레트를 차량마다 새로 만들지 않습니다. 차량 부품은 해당 차량을 소유자로 참조하고 차량 제거 시 정리합니다. 공유 재고는 차량을 제거해도 차량 쪽에서 파괴하지 않습니다.

차체·바퀴·포크·관절은 지정한 위치·방향에서 직접 생성합니다. 완성된 용접 강체 조립체를 원점에서 옮겨 배치하던 초기 방식은 동시 생성 시험에서 발산하여 폐기했습니다. 서로 다른 차량의 같은 번호 바퀴끼리도 물리 충돌이 가능합니다. 물리 계산 간격은 같은 월드에 속한 차량들의 요구를 함께 고려합니다.

## 팔레트와 화물

전체 치수는 1100×1100×120mm입니다. `ContentSource/Campus/PalletFourWay1100.json`의 격자·프레임·받침별 박스가 하나의 용접된 팔레트 강체를 이룹니다. 포크 통로를 하나의 큰 충돌 상자로 막지 않습니다. 화물은 팔레트와 별개 강체이며 기본 고정 스트랩을 사용하지 않습니다. 기존 질량·마찰·포크 하중·바퀴 하중·유압 계산을 연결합니다. 질량·편심·마찰은 `Config/Payload.json`의 가정값을 사용하며, 전체 치수와 받침별 충돌 구조는 새 팔레트 형상이 우선합니다.

팔레트의 강체 루트는 첫 받침의 중심이고, 재고의 좌표는 팔레트 바닥 중앙입니다. 이 두 기준을 명시적으로 변환합니다. 화물 편심은 **팔레트 바닥 중앙**을 기준으로 적용하고, 화물과 팔레트 사이의 실제 접촉 마찰을 유지합니다. 네 방향의 통로 중심 간격과 포크 간격은 460mm, 가정 통로 폭/높이는 280/90mm입니다. 세부 형상·물성은 프로젝트 가정이며 제조사 정격의 검증 자료는 아닙니다.

## 재고·랙 상태

슬롯 256개와 재고 35개(바닥 PICK-01~03, 초기 랙 재고 32개)를 등록합니다. 초기 물리 팔레트는 바닥 3개입니다. 랙 재고는 G로 선택할 때 해당 정적 팔레트·상자 외형과 전체 장애물 충돌을 제거하고, 실제 팔레트와 화물 강체로 교체합니다. 식별자는 유지하며 같은 위치에 정적·동적 충돌을 겹치지 않습니다. 초기 차량 수와 위치는 공유 배치의 `initial_vehicles`와 `parking`에서 읽으며 현재는 3대, 예약 주차면 범위는 최대 8대입니다. 이는 아직 집지 않는 모든 재고를 계속 동적 계산하지 않기 위한 구조입니다.

각 재고 묶음은 고유 팔레트 ID(`-PALLET`)와 화물 ID(`-CARGO`)를 별도로 유지합니다. 두 ID의 연관 관계는 물리적으로 화물을 팔레트에 고정한다는 뜻이 아닙니다.

예약은 재고와 목적지 슬롯에서 독점적입니다. 다른 차량이 이미 예약한 화물은 선택할 수 없고, 점유/사용 불가 슬롯은 다시 예약할 수 없습니다. 활성 화물이 원래 슬롯에서 벗어나면 점유를 해제합니다. 슬롯 중심·높이·자세·정지 상태가 일정 시간 일치하고, 실제 랙 접촉 충격량이 있으며 지정된 대상 여부와 무관하게 실제 차량 부품의 지지가 해제됐을 때만 배치로 기록하고 다른 화물과의 점유 충돌을 거부합니다.

슬롯별 상태와 재고 예약, 차량별 센서 CSV 연결 정보는 플레이 중 `Saved/Validation/Campus/InventoryState.json`에 1초마다 기록합니다.

이 점유 갱신은 **시뮬레이터의 재고 관리용 실제 형상·접촉 관찰**입니다. 카메라 인식이나 제어기로 정답 위치를 전달하는 경로가 아닙니다. 향후 자동화에서는 센서에 기반한 인양·하역 완료 증거와 재고 전이를 결합해야 합니다. 팔레트가 4방향 진입형이어도 랙 안에서는 기둥·이웃 화물 때문에 접근 가능한 방향이 제한됩니다. 배치의 슬롯 접근 방향은 그대로 보존합니다.

## 센서와 위치 추정

깊이 영상은 기존 최대 8Hz를 유지하며, 새 팔레트의 전체 형상 탐색은 차량별 시점을 나눠 최대 2Hz로 실행합니다. 그 사이의 추적과 센서 판정은 새 표본으로 계속 갱신합니다.

차량마다 기존 엔코더·IMU·승강/압력/포크 하중·근거리/존재 센서·전후 LiDAR·전방 깊이/후방 RGB-D를 연결합니다. 자신의 부품을 구분하고 다른 지게차와 물리 재고를 감지합니다. 포크 하중 센서는 지정한 목표 팔레트뿐 아니라 자기 포크에 닿는 접촉을 측정합니다.

일반 강체의 센서는 기존 Chaos 실제 형상 읽기를 유지합니다. ISM/HISM 랙과 벽은 루트 BodyInstance가 없는 별도 인스턴스 충돌이므로, 물리와 쿼리가 모두 활성인 실제 형상에 대해 월드 가속 구조로 광선을 검사합니다. 렌더 외형·쿼리 전용 가짜 장애물·배우 ID를 감지 결과로 사용하지 않습니다.

새 팔레트의 발·상판·두 통로를 실제 깊이 표본으로 검사합니다. 상자 앞면과 팔레트 앞면이 떨어진 경우의 가설 범위를 늘렸으며 각 가설은 지지대·상판·실제 먼 반사와 통로 양쪽 경계를 다시 확인합니다. 영상이 사라지는 구간은 기존 센서 기반 제한 추적과 근거리 측정 보강을 사용합니다. 대상 ID의 정답 위치로 검출을 만들지 않습니다.

`Config/CampusSurvey.json`은 맵 생성 시 정적 부재의 조사 위치로 작성합니다. 움직이는 차량·재고는 조사 지도에 포함하지 않습니다. 초기 주차 위치는 알려진 출발 위치 사전값이고, 이후 이동은 엔코더·IMU 및 LiDAR 지도 정합으로 추정합니다. 정합에는 추정 위치 주변의 지도 부재를 사용합니다. 개방 구간에서 관측 가능한 정적 부재가 부족하면 지도 정합을 유효하다고 표시하지 않고 초기 위치+오도메트리와 정합 상실 상태를 표시합니다. 5~6번의 전역 경로 연결에서는 이 관측 사각 구간의 기준물 배치·센서 범위와 경로상의 위치 추정 유지 조건도 함께 검증해야 합니다. 이는 3D SLAM이나 창고 전체 경로 계획의 완료를 뜻하지 않습니다.

## 확인 범위

`Scripts/Test-CampusFoundation.ps1`은 실제 GPU 카메라와 물리 월드에서 1.95m 상단 팔레트 인식, 실제 랙 지지와 공중 정렬 거부, 소유권·동료 차량 감지·랙 부재/빈 공간·재고 활성화와 0/90/180/270도 진입을 시험합니다. 시험의 일정한 주행·승강 입력은 운영자 조작을 재현하는 시험 입력이며 제품의 자동 삽입 기능으로 표시하지 않습니다. 정답 위치·삽입 깊이는 시험 합격 판정과 재고 관리에만 사용합니다. 실제 인식·제어에는 센서 측정을 사용합니다.

시험은 고정 30 FPS 입력 간격을 사용하는 기능 검증입니다. 실제 FPS와 시뮬레이션/벽시계 비율은 별도로 기록하며, 3대 또는 6대의 실시간 운용 성능 보장으로 해석하지 않습니다. 최종 통과 조건·실행 로그·파일 해시는 별도 검증 기록에 보존합니다.

2026-11-12 최종 빌드에서 **단위 시험 92/92, 실제 월드 시험 7/7, 기존 단일 차량 회귀 2/2**를 통과했습니다. 실제 월드 7조건은 기본 구조·재고 전이·상단 인식·네 방향 삽입/인양/운반/하역입니다. 이 기능 시험에서 관측한 성능은 약 10~12 FPS, 시뮬레이션/벽시계 비율 약 0.33이므로 실시간 운용을 위한 최적화는 후속 6번 범위입니다. [검증 결과와 실행 조건·해시](References/CampusFoundationEvidence-20261112.json)를 확인할 수 있습니다.
