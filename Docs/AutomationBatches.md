# 자동화 구현 묶음

2026-11-05. 높이·리미트·압력 기반 승강 제어 이후의 작업 순서다. 사용자가 지정한 9개 남은 항목을 아래처럼 묶는다. 각 묶음은 구현·실제 Unreal 시험·웹·기록까지 확인한 뒤 다음 묶음으로 이어간다. 사용자 실행 파일은 계속 루트 Start.bat 하나다.

| 묶음 | 작업 | 완료 판단 | 현재 상태 |
|---|---|---|---|
| 1 | 주변 장애물 감지 + 차량 전체 정지·복구 | 두 2D LiDAR의 실제 충돌 형상 측정, 전후좌우/대각 보호 영역, 장애물 주행 정지, 필수 센서 단절/비상정지 시 주행·승강 정지, 정상 신호와 명시적 확인 후 복구 | 구현·지정 조건 검증 완료. 제동 과도 운동 제한은 LidarSafety.md 참고 |
| 2 | 주행 센서 연결 + 위치 추정 | 엔코더·IMU 기반 속도/회전 제어와 오도메트리, 2D 지도/스캔을 통한 위치 오차 보정, 슬립·센서 지연·고장 시험 | 구현·지정 조건 검증 완료. 고정 지도·출발 구역 가정 및 저마찰 토크 진동 제한은 SensorDrive.md 참고 |
| 3 | 팔레트 인식 + 삽입 판정 | 깊이 영상에서 팔레트/구멍 위치·자세·신뢰도 추정, 근거리·존재·하중 정보와 결합한 부분/완전/실패 판정 | 알려진 팔레트 계열 구현·지정 조건 검증 완료. 가림·추적·치수 사전 정보의 제한은 PalletPerception.md 참고 |
| 4 | 자동 정렬·삽입·인양·하역 | 제한 속도 작업 모드, 인식 기반 정렬/접근, 삽입·양중·랙 1/2단 적재/인출·포크 후퇴와 실패 정지 | 로컬 작업 구현·지정 조건 검증 완료. 알려진 팔레트·등록 랙 및 보호 제한은 HandlingControl.md 참고 |
| 5 | 자율주행 + 임무 관리·통합 검증 | 지도 경로 계획·추종·장애물 회피, 이동→인식→삽입→운반→하역 전체 상태 관리, 재시도/중단/재개와 실시간성 검증 | 구현·지정 조건 검증 완료. 등록 2D 구역·고정 방향 범위는 MissionNavigation.md 참고 |

3D SLAM은 기존 합의대로 후순위다. 위 순서의 주행/위치 추정은 우선 2D 범위로 진행한다. 기존 랙 자동 시험의 GT 제어를 센서 기반 자율 작업의 구현으로 계산하지 않는다. 실차 보정·전체 에너지 수지·충격/정격 검증은 별도의 물리 과제다.

1묶음은 [구성·조작·검증](LidarSafety.md)에 기록했다. 당시 단위 62/62, Native 11/11(보호 9·기존 물리 2), 실제 웹 302프레임·18열 CSV와 카메라 GPU 회귀를 확인했다. 장애물 수동 접근은 Shift 유지 중 목표 0.15m/s로 제한하며 고장·비상정지를 우회하지 않는다.

2묶음은 [센서 주행·위치 추정](SensorDrive.md)에 기록했다. 당시 단위 67/67, Native 11/11(센서 주행·위치 추정 9·기존 물리 2), 실제 웹 384프레임·26열 CSV와 카메라 GPU 회귀를 확인했다. 주행 제어의 GT 속도·방향·바퀴 회전 피드백을 대체했다. 저마찰 가속의 토크 진동, 전역 재위치 추정과 지도 밖 운행 등은 미해결 범위다.

3묶음은 [팔레트 인식·삽입 판정](PalletPerception.md)에 기록했다. 단위 71/71, 실제 GPU 조건 9개와 주행·물리 회귀 3개, 실제 웹 238프레임·29열 CSV 및 카메라 회귀를 확인했다. 이는 3묶음 완료 시점의 이력이다. 당시 미연결이던 작업 제어는 아래 4묶음에서 연결했다.

4묶음은 [자동 작업·조작·검증](HandlingControl.md)에 기록했다. 당시 단위 78/78, Native 16/16(작업·고장 11, 기존 물리 3, 인식 회귀 2), 실제 웹 6,666프레임·20열 CSV 및 카메라 회귀를 확인했다. 시작은 Start.bat → Play이며 5 바닥 인양, 6/7 랙 인양, 8/9 랙 하역, 0 취소다. 등록 구역의 경로 계획·운반 임무·복구는 [5묶음](MissionNavigation.md)에 연결했다. 과거 빌드 검증 숫자는 새 빌드의 통과 숫자로 재사용하지 않는다.

2026-11-07 5묶음: 단위 89/89, Native 12조건(임무·복구 8, 기존 인양·주행·제동 3, 실제 기본 창고 전체 임무 1), 실제 웹 10,808프레임·30열 CSV와 실제 GPU 카메라 회귀를 확인했다. 기본 창고 1단 전체 임무의 비벤치마크 실행은 평균 41.79 FPS·0.970배속이었다. 등록 지도·기준 기둥·출발 구역·알려진 팔레트 계열을 쓰는 고정 방향·평지 저속 범위이며, Editor PIE와 모든 조건의 실시간성은 보장하지 않는다.
