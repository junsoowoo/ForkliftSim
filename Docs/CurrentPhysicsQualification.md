## 1. 두 단 랙과 실제 적재 접촉

`Config/RackHandling.json`의 시험 랙은 지지면 높이 0.35 / 1.95 m, 선반 두께 40 mm다. 소유한 Warehouse 팔레트와 분리 화물의 실제 경계 기준 합산 높이는 약 1.392 m다. 하단 선반 위부터 상단 선반 아랫면까지 1.56 m이므로 여유는 약 168 mm다. 기존 배경 랙의 3단 배치를 두 단으로 수정했고 에셋의 실제 상단 경계를 기준으로 선반을 배치했다. 변경 전 맵은 Saved/Backups에 백업했다.

현재 장비의 승강 행정은 2.1 m, 이동 마스트는 2:1 체인 관계로 약 1.05 m 이동한다. 설계상 마스트 상단은 최대 약 3.525 m다. 다만 현재 맵의 시험 통로 위는 열려 있으므로 천장 충돌 통과를 주장하지 않는다. 이것은 4 m 높이의 창고를 고려한 가상 설계이며 EKS의 정격 마스트 재현이나 안전 인증은 아니다. 실제 포크와 팔레트 구멍의 높이를 비교해 삽입 높이를 정한다. 팔레트·상자·포크는 실제 충돌로 하중을 전달하며 화물을 포크나 랙에 붙이지 않는다.

`rack_place_low/high`, `rack_pick_low/high`는 작업자의 수동 조작을 대신 재생하는 **검증용 정답 상태 제어**다. 센서 인식이나 자율주행으로 표시하지 않는다. 인출 시험의 초기 팔레트는 랙 위에 놓인 상태에서 시작하고, 시작 후에는 위치를 강제로 이동시키지 않는다. 랙 반력·포크 반력·화물 지지를 확인하고 포크를 빼낸 뒤에도 지지 상태를 확인한다.

## 2. 현재 차체의 통합 시험

이전 대형 시험 차체의 결과를 현재 소형 차체에 이월하지 않는다. 현재 설정으로 정지, 무동력 감속, 구동 반작용·평지 제동·마찰 조절키, 적재 운반, 편심·얕은 삽입, 높은 적재, 턱·한쪽 턱·좌우 다른 노면, 적재 경사 제동, 화물 미끄럼·낙하, 하강을 검증한다. `Scripts/Test-CurrentPhysics.ps1`로 재현하며 `-Quick`은 핵심 3개만 실행한다.

프로젝트 루트 PowerShell에서 `powershell -ExecutionPolicy Bypass -File Scripts\Test-CurrentPhysics.ps1 -UncappedBenchmark`로 전체 32개 조건을 재현한다. 이는 기준 17개 + 랙 4개 + 시간 격자 8개 + 구름저항 비교 3개다. `-UncappedBenchmark`는 시험의 벽시계 FPS 제한만 해제하고, 엔진의 고정 시험 FPS·실제 내부 물리 간격 검사는 유지한다. 이 headless 시험의 실행 속도를 실제 창고 렌더링 성능으로 소개하지 않는다.

## 3. 수치 오차와 에너지 장부

**정하중 계측의 약 3.7% 편향을 수정했다.** Chaos 접촉 shock propagation이 접촉 해법에서 유효 역질량을 변경했다. 원래 물체 질량 자체가 잘못된 것은 아니었다. 같은 빌드에서 425 kg 팔레트·화물을 랙에 놓고 해당 설정만 끈 A/B 시험에서 반력이 약 4,013.8 N에서 이론값 4,169.25 N으로 복원됐다. 기본 설정에서 접촉 위치·속도 shock propagation을 해제했다. 질량·마찰을 임의로 조정해 결과를 맞추지 않았다. 관절의 mass conditioning / shock propagation 비활성화도 유지한다.

UE 5.6 엔진 소스 `PBDRigidsSolver.cpp`, `PBDCollisionContainerSolver.cpp`, `PBDCollisionConstraint.h`의 실제 접촉 결과와 내부 시간 처리를 확인했다. 내부 스텝 충격량을 적분하고 프레임 구간으로 나누어 힘을 기록한다. 팔레트·화물의 물리 스레드 질량도 CSV에 따로 남긴다.

새 항목은 등가 접촉 소산, 포크 소성 재중심화에서 제거된 탄성 에너지, 파손 때 제거된 탄성 에너지, 접촉 법선·접선 일 추정, 위치 보정의 의사 일, 포크 감쇠 추정이다. 실제 Unreal CSV 및 웹으로 전달한다.

- 등가 접촉 소산은 현재 모델과 수치 적분이 제거한 에너지의 추정량이다. 순수 재료 발열이나 실제 발열 실측이 아니다.
- 소성·파손 항목은 모델에서 제거된 탄성 에너지다. 실제 재료의 파괴 에너지·열 발생량과 같다고 보지 않는다.
- 접촉 일은 전체 제약 풀이 전후 평균 속도를 쓰므로 접촉과 관절 사이 교차항을 완전히 분리하지 못한다. 포크 감쇠도 표본 기반 추정이다. **이 둘은 손실 합에 추가하지 않는다.**
- 위치 보정의 의사 일은 열·마찰 소산으로 취급하지 않는다.
- 잔차는 미계상 물리 손실과 수치 오차를 함께 포함한다. `full_closure=false`를 유지한다. 잔차를 강제로 0으로 만드는 보정은 없다.

30/60 FPS와 960/1920 Hz의 동일 조건 비교는 `Config/PublicCalibration.json`에 미리 적은 허용오차를 사용한다. 충돌 순간 힘의 피크를 실제 PU 응력이나 부품 정격으로 판정하지 않는다.

## 4. 공개 사양의 적용과 보정 범위

[Logisnext가 배포하는 EKS 215a 2019 사양](https://www.logisnextamericas.com/globalassets/migration-blocks/jungheinrich/product-listing/walkie-stackers/eks-215a/eks_215a_spec_sheet-english.pdf)의 서비스 질량 3,140 kg, 폭 985 mm, 축거 938 mm, 포크 1,200×120×50 mm를 설계 기준과 대조했다. 이때 무적재라는 표현은 화물을 제외한다는 뜻이며 제조사 서비스 질량에는 배터리가 포함된다. 원 장비의 2/1x 구동, 적재 정격, 축하중, 모터 정격을 4메카넘 장비의 실측값으로 바꾸지 않는다. 원 장비의 양중 속도 0.29 / 0.31 m/s도 해당 적재·장비 조건의 비교 자료이며, 현재 400 kg 시험에 곧바로 맞추는 목표로 사용하지 않는다.

[Hickwall 제품 페이지](https://www.hit1994.com/en-US/p104-12-in-mecanum-wheel)는 HIT305AHD 하중을 3,000 kg으로, [제조사 카탈로그 p7](https://www.hit1994.com/pdfimages/2025HIT_pdfc_2608302_264417_5083344.pdf)은 단일 휠 750 kg으로 표기한다. 상충을 기록하고 웹 하중비를 `null`로 중단했다. 질량 40 kg·305×156 mm·8롤러는 비교 제품의 공개 값이다. 현재 50 kg·300×160 mm·12롤러 휠의 관성이나 정격을 이 제품으로부터 만들지 않는다.

카탈로그의 750 kg을 그대로 사용하면 4개 합계 3,000 kg으로 현재 무적재 질량 3,140 kg에도 부족하다. 따라서 이 제품은 적합성이 확인된 선정 부품이 아니라 비교 자료다. 현재 커스텀 휠의 허용 하중은 미확정으로 남긴다.

[Blickle PU 자료 p15](https://www.blickle.us/en-us/-/media/project/blickle/global-web/service/mediathek/prospekte/pdf/us/competence_in_polyurethane_240923_en_us.pdf?fh=d84b7ddc2d5702224c25dde9e3e7828d#page=15)의 구름저항은 200 mm 새 휠, 300 kg, 동일 브래킷의 실험실 조건이며 재료별 약 0.7~1.0%다. 0.007·0.009를 **재료 비교용 시험 조건**으로 사용한다. 베어링 손실을 중복 합산하지 않도록 이 비교 시험에서 별도 베어링 저항을 끈다. 현재 메카넘과 바닥의 실측 계수로 가져오지 않는다. 기본 Crr 0.015와 마찰 0.9/0.8은 가정으로 유지한다.

원문과 해시는 `Saved/Research/PublicCalibration-20261031` 및 `Docs/References/PublicCalibrationDownloads-20261031.json`에 기록했다. Blickle은 웹 도구의 제조사 PDF 텍스트를 확인했으나 직접 PDF 다운로드는 TLS/HTML 응답으로 실패했으므로 원문 보관을 주장하지 않는다. 기존 Cascade 포크 항복·Shell 유체 물성 참고는 유지한다.

**실측 자료가 없어도 공개 근거와 해석 검증은 수행한다. 다만 공개되지 않은 현재 장비의 관성·마찰·펌프 맵을 임의로 만들고 실제 측정값이라고 부를 수는 없다.** `hardware_calibration_complete=false`는 유지한다.

## 중간 실패 기록

기존 원통 접촉의 한쪽 턱 제동은 60 FPS·960 Hz, 30 FPS·960 Hz, 60 FPS·1920 Hz에서 실패했다. 반복 횟수 64/32 및 CCD 해제 진단도 해결하지 못했다. 접촉 보정에서 큰 양의 의사 일이 발생하고 실제 저장 에너지가 입력 예산을 넘었다. 이를 정상 전복이나 물성 부족으로 판정하지 않는다. `Saved/Validation/Performance/Priorities4-RejectedNumerics.json`에 실패와 시간 간격 비교를 보존한다. 현재 수정 후보의 결과와 구별한다.

해석적 원통 접촉 후보는 기존 일반 타이어의 원통–박스 면/평행 모서리 투영을 경량 메카넘의 지지 원통에도 적용한다. 실제 원통의 반지름 150 mm와 지지 폭 140 mm를 사용하고, 횡방향 구동 마찰은 기존 메카넘 등가 모델이 처리한다. 기본 바깥면 보정만으로 30 FPS·960 Hz 및 60 FPS·1920 Hz의 옆면 접촉 실패가 남아, 유한 원통 끝면과 기울어진 박스 모서리의 법선·접촉점을 추가로 계산했다. 박스 외향 법선 영역 안에서 분리 거리를 최대화하고, 실제 면 접촉이면 옆면 모서리의 잘못된 법선 대신 해당 면의 접촉점을 사용한다. 유한 모서리를 벗어난 꼭짓점 및 지원하지 않는 형상은 Chaos 충돌을 유지한다. 별도 단위 시험에서 cap/rim·스큐 모서리·외향 법선과 실제 경계 위 접촉점을 검사한다. 새 형상 시험을 포함한 전체 단위 시험은 37/37 통과했다. 기존 다각형 접촉에서 나타난 구름저항 0.007 입력의 과도한 감속(환산 약 0.0114)이 후보에서 약 0.006998로 줄었다. 계산한 힘을 결과에 맞춰 보정하거나 차체를 강제로 이동한 것이 아니다. 기본 변경 후 회귀와 시간 간격 비교를 별도로 기록한다. CCD는 기본으로 유지하며 과거 접촉은 `-NativeReducedSupport` 진단 옵션으로 재현한다.

동시 시험이 같은 밀리초 폴더명을 만들 수 있는 보고서 경로 문제도 수정했다. 이제 실행 폴더에 GUID를 붙이고 실제 네이티브 명령행이 요청한 FPS·모델·접촉 옵션과 일치하는지 검사한다. 충돌한 `Mecanum-20261031-080049-352`의 통합 manifest/results는 무효로 표시하고 원본 로그·GUID CSV만 보존한다. 이 폴더의 결과를 최종 통계에 포함하지 않는다.

## 제동 접촉과 수렴 보정

형상 보정만으로 해결되지 않은 한쪽 턱 제동 문제를 별도로 수정했다. 기존 접선 스프링은 감쇠력까지 마찰 한계로 자른 뒤 그 값을 탄성 변위로 되돌려, 큰 충격에서 가짜 탄성 에너지를 저장할 수 있었다. 이제 수동적인 감쇠 충격량을 먼저 풀고, 남은 마찰 한계 안에서 암시적 탄성·미끄럼 복귀를 계산한다. 자유 롤러 방향과 구동 방향 사이 점 역질량의 교차항도 포함한다. 무작위 결합 관성 2,000개 조건에서 접촉 충격량 전후 운동·탄성 에너지 부등식과 마찰원 한계를 검사한다.

등가 롤러 법칙은 실제 지지 접촉에만 적용한다. 원통 끝면이 턱 옆벽에 닿은 것을 추가 지지 롤러로 해석하지 않는다. 접촉 쌍에 지지점이 하나라도 있으면 해당 쌍의 기본 마찰을 끄고 유효 지지점에 등가력을 주는 근사이며, 혼합 접촉에서 점별로 완전한 재료 모델을 푸는 것은 아니다. 구름저항은 물리 스레드의 지지 하중을 사용하고, 한 스텝 안에서 회전 방향을 과도하게 뒤집어 에너지를 늘리지 못하도록 실제 관성으로 토크를 제한한다. 접촉이 끊기면 남은 탄성 상태를 제거하고 장부에 기록한다.

질량·마찰·접촉 강성 200,000 N/m·감쇠 2,000 Ns/m는 이 수치 보정을 위해 바꾸지 않았다. 이 강성·감쇠는 측정된 PU 특성값이 아닌 등가 모델의 설계값이다. 전체 단위 시험은 현재 수정본에서 **38/38 통과**했다. 16/16회 솔버는 960/1920 Hz 사이 잔차 차이 기준을 약간 초과했고, 같은 물성의 32/32회는 기존 기준을 통과했다. 최종 회귀와 성능은 아래 결과 파일에 따로 기록한다.

후속 회귀에서 자유 바퀴의 예측 변위만 사용하면 브레이크·차체 관절이 잠긴 경사면에서 접촉 스프링이 인위적으로 풀리는 문제를 확인했다. 반대로 모든 충격 구간에 관절 계산 후 상태 갱신을 적용한 후보는 턱에서 실패했으며 `Priorities4-RejectedSolvedContact.json`으로 보존했다. 현재 모델은 풀이 전후 접촉점 속도가 모두 0.3 m/s 미만, 휠 각속도 0.5 rad/s 미만인 제동 구간에서 정지 마찰 저장량을 실제 풀이 후 움직임으로 갱신한다. 이때 저장량은 접촉 포트 일과 마찰 한계로 제한한다. 그 밖의 충격 구간은 수동적 자유 바퀴 예측을 유지한다. 초기 후보의 하중 변화율 조건은 강체 접촉 충격량의 변동 때문에 정지 마찰을 과도하게 해제해 제외했고, 진단 기록으로만 남겼다. 이 전환 기준과 에너지 제한은 수치 정규화 가정이며 실측 PU 특성이나 다물체 접촉의 완전한 에너지 폐합 증명이 아니다.

## 실제 창고 화면과 실행 성능

같은 최종 DLL로 다른 Unreal 시험을 모두 종료한 뒤 `/Game/Maps/WarehouseLab`, 1280×800, 960Hz·32/32회, balanced 렌더링, 기존 전방 ToF·후방 RGB-D와 실제 웹 전송을 켜고 실행했다. benchmark나 고정 시험 FPS를 사용하지 않았다. 시뮬레이션 약 53초의 2,964개 게임 틱 표본에서 **평균 56.14 FPS, p95 28.93 ms, 실제 진행 0.9838배, 마지막 120프레임 평균 43.79 FPS**였다. 짧은 단독 오프스크린 실행이며 지속 60 FPS나 에디터 PIE 성능을 보장하는 값이 아니다.

포크 높이 2.088 m에서 전방 카메라 높이는 2.133 m였고, 전후방 장착 위치 오차는 각각 10⁻⁶ cm 미만이었다. 센서의 최소 거리 밖 결측을 그대로 표시한다. 이 렌더링 캡처는 랙 하중 전환 완료 전에 종료하므로 랙 작업 통과 증거와 구별한다. 완료된 네 랙 시험은 위 네이티브 보고서로 확인한다.

기본 관찰 시점이 뒤쪽 배경 랙을 통과해 장비가 가리는 경우를 확인했다. 이번 범위에서 관찰 카메라나 센서를 바꿔 숨기지 않았다. 기존 마우스 드래그의 회전·휠 줌과 **V 상단 검사 뷰**로 확인할 수 있다. 상단 검사는 차체 데크의 렌더만 숨기고 질량·충돌·관절은 유지한다.
