# ForkliftSim

Unreal Engine 5.6.1 기반 **물리·센서·제어를 검증하는 무인 지게차 프로젝트**입니다.
최종 목표는 센서로 팔레트를 찾아 정렬하고, 들어 올려 운반·하역하는 지게차 한 대입니다.

**자동화 5묶음 — 경로 주행·운반 임무:** 등록한 2D 지도와 센서 위치 추정으로 경로를 계획하고, 실제 LiDAR 장애물 관측에 따라 재계획합니다. 인식·삽입·인양→낮게 운반→랙 1/2단 하역을 임무로 연결했습니다. **Start.bat → Play → PageDown/Up으로 1/2단 선택 → Enter**로 시작합니다. **Backspace** 일시정지, **]** 명시적 재개, **0** 취소, **X** 비상정지, **Y** 고장 확인, **R** 초기화입니다. 웹에 실제 임무 상태·추정 위치·계획 경로와 수신 CSV 30열을 추가했습니다. 알려진 출발 구역·등록 지도/랙·고정 방향·평지 저속 범위이며 3D SLAM은 포함하지 않습니다. [전체 조작키·시험 조건·제한](Docs/MissionNavigation.md). 아래 1~4묶음의 완료 숫자와 당시 미연결 설명은 각 단계의 이력입니다.

최종 검증은 단위 **89/89**, Native **12조건**, 실제 웹 **10,808프레임·30열 CSV** 및 실제 GPU 카메라 회귀입니다. 기본 창고의 고정 기준 기둥 3개는 Play에서 자동 배치하며 실제 LiDAR 측정으로 지도 보정을 유지합니다. 같은 빌드의 기본 창고 1단 전체 임무는 평균 **41.79 FPS·0.970배속**으로 완료했습니다. 카메라·물리 주기는 유지하고 필요 없는 단계의 통로 탐색 계산을 줄였습니다. [최종 증거](Docs/References/MissionEvidence-20261107.json).

공개 저장소에는 프로젝트 소스·직접 제작한 모델·맵·웹·검증 요약을 포함합니다. Fab Warehouse 원본과 번들 문서·미리보기, 내려받은 제조사 원본은 로컬에 보관합니다. 다른 PC에서는 [모델링 안내](Docs/WarehouseModeling.md)에 따라 본인 권한으로 Warehouse 에셋을 추가해야 합니다. `Saved`의 원본 실행 CSV·로그와 빌드 출력은 업로드하지 않으며, 검증 요약·출처·해시는 `Docs/References`에 보관합니다.

**자동화 4묶음 — 로컬 자동 작업:** 깊이 인식과 센서 판정에서 자동 정렬·삽입·유압 인양·후퇴·랙 1/2단 하역을 연결했습니다. `Start.bat` → Play 후 **5** 바닥 인양, **6/7** 랙 1/2단 인양, **8/9** 랙 1/2단 하역, **0** 취소입니다. 수동 입력과 비상정지는 작업보다 우선하며, 웹에서 실제 단계·정지 사유·명령과 20열 CSV를 확인합니다. 단위 78/78, Native 16/16, 실제 웹 6,666프레임과 카메라 회귀를 통과했습니다. 알려진 팔레트 계열·등록된 가까운 랙 작업 범위이며 창고 전체 경로 계획은 후속입니다. [작업 순서·조작·제한·검증](Docs/HandlingControl.md).


**자동화 3묶음 — 팔레트 인식·삽입 판정:** 전방 실제 깊이 영상에서 현재 Warehouse 팔레트 계열의 앞면·두 통로와 위치·각도를 찾고, 근거리·존재·좌우 하중·높이 측정과 결합해 정렬 불량·부분 삽입·완전 삽입 증거·지지 상태를 구분합니다. 전방 카메라는 포크 위쪽으로 옮겨 아래로 기울였으며 두 카메라 구성은 유지했습니다. 초록 통로 표시와 웹 실시간 판정·29열 CSV를 추가했습니다. 단위 71/71·Native 12/12(실제 GPU 9·주행/물리 3)·실제 웹 238프레임과 카메라 회귀를 통과했습니다. 알려진 치수·제한된 가림 추적을 쓰는 모델이며 자동 삽입은 다음 묶음입니다. [구성·실제 기록·제한](Docs/PalletPerception.md).

**자동화 2묶음 — 센서 주행·2D 위치 추정:** 기본 integrated에서 네 바퀴 엔코더·IMU 측정값으로 토크와 방향을 제어하고, 취득 시각 이력을 반영한 오도메트리를 고정 창고 지도·LiDAR로 보정합니다. 시작할 때 이동 입력을 놓고 정지 바이어스 추정을 기다립니다. 주행 센서 고장·100ms 명령 만료는 전체 정지와 Y 복구에 연결했습니다. 단위 67/67·Unreal 11/11(새 주행 9·기존 물리 2)·실제 웹 384프레임/26열 CSV와 기존 카메라 회귀를 통과했습니다. 출발 구역과 정적 지도를 안다고 가정하며, 매우 낮은 마찰의 가속에서는 토크 진동이 남아 있습니다. 지도 작성·전역 재위치 추정·자율주행·팔레트 인식은 후속입니다. [구성·수치·제한](Docs/SensorDrive.md). 아래 이전 센서 묶음의 검증 숫자·미연결 설명은 각 단계의 이력입니다.

**자동화 1묶음 — 주변 감지·차량 정지/복구:** 기본 integrated에 2D LiDAR 2개(각 270광선·10Hz)를 연결했습니다. 실제 충돌 형상을 측정해 장애물이 보호 영역에 들어오면 주행을 정지하고, 센서 고장이나 X는 주행·승강을 함께 정지합니다. Y는 정상 수신·중립 상태에서 복구 확인, I는 광선 표시, Shift 유지 중에는 팔레트 수동 접근용 저속 작업 모드(목표 0.15m/s)입니다. Shift는 장애물 주행 정지를 일시 해제하지만 고장·비상정지는 우회하지 않습니다. 웹에 실제 스캔·정지 상태·별도 CSV를 추가했습니다. [구성·검증·제동 과도 운동 제한](Docs/LidarSafety.md), [자동화 작업 묶음](Docs/AutomationBatches.md). 주행 센서 피드백·위치 추정·팔레트 인식·삽입 판정·자율 작업은 후속입니다.

**현재 기본 모델:** `Start.bat`는 경량 메카넘 접촉 모델(960Hz·32/32회)과 balanced 렌더링을 사용합니다. 실제 바퀴 하중·접지 한계·슬립·축 반작용·팔레트/화물 접촉·유압을 계산하며, 롤러 48개의 개별 운동은 기본 모델에서 생략합니다. 기존 정밀 모델은 `Start.bat -MecanumModel detailed`로 보존합니다. [이전 성능·센서 구성](Docs/PerformanceAndSensors.md).

**현재 물리 우선 작업 4개:** 두 단 랙의 실제 적재·인출, 소형 차체 적재 노면 시험, 정하중 편향·접촉 수치 오차 수정, 공개 사양 대조를 진행했습니다. 현재 결과와 재현 방법은 [CurrentPhysicsQualification.md](Docs/CurrentPhysicsQualification.md)를 기준으로 확인하세요. 이전 정밀 휠·일반 타이어의 시험 수치를 현재 결과로 재사용하지 않습니다. 공개 자료 보정은 실차 실측 보정이나 커스텀 메카넘의 허용 하중 인증을 뜻하지 않습니다.

관절 센서 추가 전 물리 기준 빌드의 네이티브 조건 **32/32**, 시간 격자 비교 **8/8**, 단위 시험 **38/38**, 실제 웹 **600프레임·57열 CSV** 검증을 통과했습니다. 당시 실제 창고·기존 두 카메라·웹 전송을 켠 짧은 단독 실행은 평균 **56.14 FPS**, 진행 **0.984배**였습니다. 전체 에너지 폐합·실차 보정·충격 피크/휠 정격 판정은 미완료이며, 기본 관찰 시점의 랙 가림과 수동 검사 방법도 위 문서에 기록했습니다.

**관절 센서 첫 묶음:** 바퀴 출력축 엔코더 4개(100Hz), 캐리지 높이 센서(50Hz), 상·하단 리미트(100Hz)를 기본 integrated에 추가했습니다. 20ms 지연·잡음·양자화·누락·250ms stale 판정과 실제 웹/별도 센서 CSV를 제공합니다. **U**는 센서 통신 고장 주입/복구, **R**은 리셋입니다. 단위 **43/43**, 센서·물리 네이티브 **8/8**, 실제 웹 **1,091프레임·19열 CSV**를 확인했습니다. 새 센서 출력은 아직 구동·승강 제어에 연결하지 않았습니다. [구성·측정 의미·검증](Docs/JointSensors.md).

**IMU·압력·좌우 포크 접촉 하중:** 다음 센서 묶음을 기본 integrated에 추가했습니다. 현재 빌드의 단위 48/48·Native 9/9·실제 웹 538프레임·21열 CSV 검증과 기존 카메라 GPU 회귀를 통과했습니다. 각각 100Hz로 실제 물리 상태를 읽고 잡음·바이어스·양자화·포화·지연·누락을 적용합니다. 웹 실시간 값과 별도 CSV를 제공하며 U로 통신 고장을 함께 주입합니다. 가상 계측 모델이며 화물 저울·실측 보정·자동 제어는 아닙니다. [측정 정의·설정·검증](Docs/DynamicsSensors.md).

**센서 기반 승강 제어:** 현재 빌드의 단위 57/57·Native 9/9(센서 제어 7·기존 물리 비교 2)·실제 웹 788프레임/19열 CSV와 카메라 GPU 회귀를 통과했습니다. 기본 integrated에서 Q/E 목표 높이를 높이·리미트·압력 센서로 제어합니다. 필요한 센서가 끊기거나 밸브 명령이 만료되면 승강 정지를 유지하며 정상 신호 복구 후 Y 확인을 요구합니다. 복구 시 현재 측정 높이를 새 목표로 잡습니다. 주행은 수동이며 팔레트 인식·삽입 판정·자동 삽입은 미연결입니다. [제어 경로·설정·검증](Docs/SensorLiftControl.md). 아래 개별 센서 묶음의 검증 숫자와 당시 미연결 설명은 각 단계의 이력입니다.

**포크 근거리·존재 센서:** 전방 거리 4개와 위쪽 물체 감지 4개를 기본 integrated에 추가했습니다. 현재 빌드의 단위 52/52·네이티브 6/6·실제 형상 7/7·웹 461프레임/17열 CSV 검증을 통과했습니다. 실제 포크 조각을 따라 승강·휨을 반영하고 웹 실시간 값·별도 CSV를 제공합니다. L은 광선 표시, U는 센서 통신 중단/복구입니다. 물체 감지가 팔레트 인식·완전 삽입 판정·자동 제어를 뜻하지는 않습니다. [장착·측정 의미·검증](Docs/ProximitySensors.md).

**전방 깊이 + 후방 RGB-D:** Play 화면 오른쪽에 승강형 전방 깊이 영상과 차체 고정 후방 RGB 영상을 표시합니다. **O**는 후방 RGB/깊이 전환, **P**는 두 센서 촬영·표시 켜기/끄기입니다. 각 320×180·최대 8Hz이며 실제 장면 깊이에 범위·잡음·누락·지연을 적용합니다. 웹에도 실제 센서 중심 거리·유효 비율·측정 나이가 갱신됩니다. `Config/Cameras.json`으로 조정하며 `Start.bat -NoCameraViews`로 끌 수 있습니다. [구성·조작·측정 정의·검증](Docs/CameraSensors.md).

이전 RGB 관찰 화면 단계의 1280×800 오프스크린 30초 실행은 평균 약 **87 FPS**, 진행 약 **0.97배**였습니다. 현재 물리·깊이 센서 단계의 성능과 구분하며, 에디터 PIE나 모니터 표시 FPS 보장값은 아닙니다. 당시 경량 물리 회귀 15/15·물리 단위 시험 33/33·실제 웹 537프레임 [기록](Docs/References/RealtimeMecanumValidation.json)도 보존합니다. 깊이 센서 추가 당시 단위 시험은 36/36이었고, 접촉·저항 수치 보정 당시 단위 시험은 38/38, 관절 센서 추가 당시에는 43/43이었으며, 이후 묶음의 현재 검증은 각 센서 문서에서 확인합니다. 실제 GPU 거리·near/far 결측·지연·RGB-D 동기 검증 이력도 보존합니다. 팔레트 검출·센서 기반 제어·2단 자동 적재·3D SLAM은 후속 단계입니다.

**창고·장비 모델링:** 기본 `Start.bat`는 소유한 Fab Warehouse 에셋의 작은 창고와 실제 규격을 참고한 무인 지게차 모델을 엽니다. 0.985m 외폭·0.938m 축간거리로 실제 물리 배치를 조정하고 4개 메카넘을 유지합니다. 작업 팔레트는 21개 판재 접촉 형상, 화물은 별도의 느슨한 강체로 연결했습니다. [치수 출처·가정·실행 방법](Docs/WarehouseModeling.md)을 확인하세요. 모델링·통합 검증 뒤 카메라와 관절 센서를 추가했습니다.

**5번 물성 근거 정리 + 3번 손실 계측 보강:** 실제 산업용 메카넘의 공개 사양과 현재 가상 휠을 구별하고, 바퀴별 실제 질량·관성·프레임 평균/내부 스텝 하중을 웹으로 전달합니다. 빠졌던 체인 감쇠 손실도 별도 합산합니다. 이번 최종 빌드의 선택 회귀 5/5·단위 시험 32/32·실제 웹 600표본/192열을 확인했습니다. 한쪽 턱의 관찰 내부 충격 피크 약 96 kN은 강체 모델 진단값이며 실제 정격 판정에 쓰지 않습니다. 실측 물성 보정과 전체 에너지 폐합은 완료되지 않았습니다. [근거·비교·보정에 필요한 자료](Docs/MecanumPropertyCalibration.md).

**0.18 수치 오차 수정 이력:** 메카넘·포크·팔레트/화물·유압과 실제 Unreal 웹 계측을 함께 사용합니다. 롤러의 대칭 회전 적분·베어링 반작용, 접촉 계산 간격, 브레이크 기준각의 부호를 수정했습니다. 이 이력의 정밀 모델은 **1920Hz·32/32회**입니다. 현재 기본 모델과 구분하며, 실제 진행 배율과 게임 FPS는 웹에서 확인할 수 있습니다.

## 실행

실행 환경: Unreal Engine 5.6.1과 빌드된 프로젝트. 실행 파일은 Windows 기본 PowerShell을 사용하며,
PowerShell 7 설치나 `pwsh` PATH 설정이 필요하지 않습니다.
소스 빌드에는 추가로 Visual Studio 2022 C++ 도구와 Windows SDK가 필요합니다.
빌드·시험 스크립트도 Windows 기본 PowerShell 5.1과 호환됩니다.

현재 PC에서는 빌드가 되어 있으므로 **`Start.bat`를 더블클릭하고 Play**를 누르면 됩니다.
기본 통합 시험장에는 팔레트·화물, 유압 포크, 바퀴 탄성·저항과 경사로가 포함됩니다.
기존 실행기 14개는 하나로 통합했습니다. 앞으로 기능을 추가해도 이 파일을 계속 사용합니다.
GitHub에서 새로 내려받은 경우에는 아래 Build를 먼저 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Build.ps1
.\Start.bat
# 에디터 없이 시험장 창만 실행할 때:
.\Start.bat -Game
# 필요한 경우에만 이전 시험장 선택 (기본은 integrated):
.\Start.bat -Mode tyre
.\Start.bat -Mode payload -Game
# 시작 노면 선택. 실행 중에는 T로 변경할 수 있습니다.
.\Start.bat -Terrain flat
```

`-Mode`는 `integrated`, `payload`, `hydraulic`, `tyre`, `terrain`, `stability`, `drive`, `lift`, `rollover`입니다.
전도 재생(`rollover`)은 자동 종료되는 시험 창으로 실행하고, 나머지는 기본 에디터 실행입니다.
엔진 설치 위치가 다르면 `-EngineRoot "D:\Epic Games\UE_5.6"`를 지정합니다.
`Scripts/Start.ps1`이 실행 구성을 관리하며, `Scripts/Run.ps1`은 내부 실행 도구입니다.

`ForkliftSim.uproject`를 Unreal Editor로 열고 Play를 눌러도 됩니다. 시작 맵은 엔진 내장
`/Engine/Maps/Entry`이며, GameMode가 시험장·조명·카메라·포크·팔레트를 실행 시 생성합니다.
편집기에서 Play 전 빈 맵으로 보이는 것은 정상입니다.

`공부` 같은 한글 상위 경로를 MSVC가 처리하지 못하는 문제를 피하기 위해 Build.ps1은
사용자의 TEMP에 영문 디렉터리 junction을 만듭니다. 원본 프로젝트는 이동·복제되지 않습니다.
생성된 Binaries, Intermediate, Saved, 빌드 캐시는 Git에 올리지 않습니다.

## 승강 시험장 구현 (기존 0.1)

- 고정된 마스트와 실제 질량을 가진 승강 캐리지·포크, 1축 물리 가이드
- 포크와 별개로 시뮬레이션되는 팔레트·화물 강체와 삽입구가 있는 충돌 형상
- 최대 인양력, 목표 승강 속도·가속도 제한, 가이드 마찰·감쇠
- 접촉 마찰 변경, 중력에 의한 하강, 힘 제한에 걸릴 때 정지·고장 감지
- 높이 센서 20 Hz, 1 mm 양자화, 50 ms 지연, 센서 끊김 주입
- 센서 피드백을 사용하는 속도 PI 제어와 포화 시 적분 누적 제한
- 실제 높이·속도·가속도·팔레트 상승량과 명령·센서값을 별도로 표시
- 승강 → 유지 → 하강 시험, CSV 기록, 무화면 자동 시험

제어기는 팔레트의 실제 질량이나 실제 높이를 직접 읽지 않습니다. 실제 위치와 속도는 센서
모델의 입력과 평가용 기록에 사용합니다. 캐리지 질량만 중력 보상에 사용합니다.

## 조작

| 키 | 동작 |
|---|---|
| SPACE | 승강·유지·하강 시험 시작 |
| R | 시험 리셋, 이전 CSV 저장 |
| M | 화물 질량 변경: 100 / 250 / 500 / 1,000 kg, 리셋 |
| T | 최대 인양력 변경: 1,500 / 6,000 / 14,000 N, 리셋 |
| F | 접촉 마찰계수 변경: 0.2 / 0.6 / 0.9, 리셋 |
| X | 높이 센서 갱신 중단/재개. 고장 해제는 R |
| C | 카메라 시점 변경 |

영구 설정은 `Config/ForkliftLab.json`에 있습니다. JSON을 수정한 뒤 다시 실행하면 적용됩니다.
고장 시에는 현재 위치를 고정하는 **이상적인 기계식 잠금**을 사용합니다. 실제 유압 브레이크를
재현한 것은 아닙니다. 순수 수직 시험에서는 접촉 마찰만 바꿔도 큰 차이가 없을 수 있습니다.
마찰의 횡방향 효과는 이후 삽입·급정지·기울임 시험에서 검증합니다.

## 시험과 기록

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Test.ps1
# 또는 -Mode Model / -Mode Physics
```

- 모델 시험: SI/Unreal 단위 변환, 힘·명령 가속도 제한, 설정 유효성 검사
- baseline: 독립 팔레트가 실제로 올라갔다가 바닥으로 돌아오는지 확인
- overload: 1,500 N으로 기본 화물을 들지 못하고 힘 한계 고장으로 전환되는지 확인
- sensor_timeout: 센서 갱신 중단 시 구동 명령 해제와 잠금 상태 전환 확인

`Saved/Telemetry/*.csv`에 시간, 상태, 목표 높이, 실제 높이, 센서 높이·시각,
실제 속도·가속도, 명령 속도, 인양력, 가이드 저항, 화물 질량, 마찰, 팔레트 상승량을 기록합니다.
`Saved/Logs`에는 시험별 로그가 남습니다. CSV는 리셋·정상 종료·사이클 완료 시 저장되므로
강제 종료 시 마지막 기록이 보존되지 않을 수 있습니다.
각 CSV 옆 `.meta.txt`에는 엔진 버전, 기본 설정, 키 조작으로 바뀐 활성 파라미터와
실제 물리 바디 질량을 함께 저장합니다.

## 모델의 범위

수치는 학습용 설계 가정이며 특정 제조사 장비의 검증된 파라미터가 아닙니다.
승강 시험장에서는 차체가 고정되어 있고 유압은 직접 수직 힘을 내는 액추에이터로 단순화했습니다.
마스트 롤러·체인·유압 회로·프레임 변형·전복 안정성은 아직 재현하지 않습니다.
팔레트와 화물은 하나의 용접 강체로 모델링하며, 포크에는 용접하지 않습니다.
캐리지 조립체 질량을 캐리지 60%·포크 각 20%로, 팔레트 질량을 상판 40%·세 받침 각 15%·
세 하판 각 5%로 나눕니다. 화물에는 별도 화물 질량을 부여하고 용접 후 실제 총질량을 검사합니다.
질량 분포 비율은 가정이며 실물 보정은 후속 단계입니다.

GPU 메모리 4 GB 노트북에서 작은 장면을 개발하도록 DX11, Lumen/레이 트레이싱 끄기,
가벼운 기본 형상을 사용합니다. 실제 성능은 장면과 실행 중인 프로그램에 따라 측정해야 합니다.
